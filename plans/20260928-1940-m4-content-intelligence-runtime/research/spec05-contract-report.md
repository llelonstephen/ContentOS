## Executive contract

- Scope: `TaskContractRevision -> AudienceState -> StrategyHypothesis -> deterministic Strategy Gate -> ContentArchitecture -> ContentUnit[] -> ContentCandidate[] -> SPEC06` (§1, §4).
- Doctrine: explicit audience/strategy/architecture; immutable candidate; rewrite creates new candidate; model output is neither truth nor evidence; unknowns/assumptions/governance survive generation; exact RunConfig only; no hidden state, latest lookup, or stale-worker commit (§3).
- Canonical entities are frozen upstream; SPEC05 introduces none. Strategy Gate is a deterministic process, never a `StrategyGateResult` entity; outcome/reasons live in StageExecution metadata (§5–6).
- Normal path requires exact task-bound `FINAL_FOR_DECISION` audience, grounded strategy, `PROCEED` gate, admitted architecture, schema-valid candidate, then SPEC06 evaluation. `PROCEED|BLOCKED|HUMAN_REVIEW_REQUIRED` are process outcomes (§13, §31–40, §43, §86, §151).

## Cross-cutting authoritative requirements

- RunConfig (§57–58): candidate and DecisionSnapshot `run_config_id` equal; pins prompt/model/tool/schema/retriever/evaluator/runtime revisions; no `latest/current/active` resolution after run start.
- Context (§59–63, §110–119): include exact Task, final audience, strategy, architecture/units, relevant epistemic/applicability/guidance/source refs, RunConfig; minimize without dropping constraints; distinguish control/canonical/untrusted/style layers; source text cannot alter authority; tools pinned, least-privilege, auditable; admitted source use obeys SPEC08; no secrets/cross-tenant data.
- Meaning preservation (§64–83): payload follows pinned schema, Task format/language/market/jurisdiction/brand/product/constraints/risk/budget and Channel capability; assumption stays assumption, unknown stays unknown, governance hard rule stays hard, guidance stays guidance; Outcome/metric targets do not prove causality/performance; budget/count never weakens gates.
- Idempotency (§87–91): request identities SHOULD include cycle + exact refs + RunConfig + slot + canonical input hash; exact retry has at most one canonical effect per slot, while intentional alternatives use distinct slots; material audience input change is a new state, not retry.
- Concurrency/state change (§92–104): all stages use StageExecution; validate cycle/fence/lease/idempotency before pre-freeze writes; FREEZING/cancellation/supersession reject late authority; cross-cycle reuse requires explicit exact compatibility/revalidation; material audience/knowledge/governance/strategy/rights/risk changes recompute affected immutable downstream objects.
- Persistence (§123–130): validate all closure and fence conditions inside short transactions, insert immutable object(s), write outbox event, commit; provider work outside transaction; timeout permits retry/pinned fallback/failure/human flow, never invented content or unpinned substitution.
- Audit (§112–115, §131–136): deterministic input selection/ref resolution/gates/schema/config/closure/fencing/idempotency; hash never replaces IDs; observability includes run/cycle/stage/object/config/hash/revisions/provider/duration/retry/reasons/fence; candidate trace traverses strategy audience/propositions/limits and architecture units/propositions; replay reads stored candidate, reproduction is distinct.
- Fail closed (§121–122): missing final audience, blocking gap, absent/contradicted/insufficient required state, hard governance block, identity/config mismatch, stale context, malformed output, stale fence, or tenant violation cannot create release-eligible downstream state.

## Exact SPEC06 boundary

- SPEC05 creates content; SPEC06 evaluates content. SPEC05 owns no AssertionValidationResult, CompositeImpressionAssessment, QualitativeEvaluation, risk score, final release decision, publication, measurement, or learning (§2).
- Handoff only after candidate exists, task/strategy/architecture/RunConfig closure passes, payload parses, and decision path is valid/writable; payload: candidate/task/strategy/architecture/RunConfig IDs, content, relevant pinned context refs (§105, §151).
- SPEC06 exclusively owns canonical ContentAssertion extraction/creation, AssertionPropositionLink behavior, AssertionValidationResult, CompositeImpressionAssessment, QualitativeEvaluation, and validation closure. Generator claim annotations are non-authoritative; generator cannot self-certify `high quality`, `safe`, `supported`, or `ready` (§105–107).
- Any rewrite/qualification repair creates a new candidate and receives fresh SPEC06 evaluation; no inherited validation. SPEC06 must catch unsupported generated assertions; release gates stay closed (§70, §74, §102–104, §157).

## v1.0.1 patch closure (§50, §52, §154A)

1. Supplemental factual Propositions introduced by Architecture must pass the same factual-proof admission rule as Strategy Gate: exact decision-time EpistemicState exists; `support_status` is neither `CONTRADICTED` nor `INSUFFICIENT`; unknown handling preserved; material strategy meaning/risk/governance change creates new StrategyHypothesis and reruns gate.
2. Architecture generation MUST NOT receive the unrestricted datastore; every context item must be explicitly scoped, decision-relevant, tenant/workspace-authorized, and attributable to canonical input or pinned config.
3. Patch changes only these two demonstrated v1.0 blockers; locked suite stays exactly 80 adversarial + 32 preflight, and adds no freeze criterion.

## Mechanical verification blueprint

- Unit/table tests: all gate truth-table permutations, exact reason codes, closure validators, supplemental proposition rule, schema/order/payload/config validation, instruction-layer parser, state-change classifier.
- Property tests: immutability/append-only invariants; same canonical inputs => semantically equivalent gate result; changed material input => changed hash/no stale cache; exact retry <=1 effect/slot; distinct slots remain distinct; no cross-tenant references.
- Integration tests: transaction + outbox atomicity; provider outside transaction; frozen/cancelled/superseded/lease-takeover races; governance refresh; rewrite/qualification new candidate + fresh SPEC06 handoff; successor-cycle explicit reselection.
- Static checks: forbidden mutable updates; forbidden `CURRENT|LATEST|ACTIVE` runtime config resolution; domain dependency/tenant filter enforcement; no new canonical entity or competing decision truth; no external-effect adapter reachable from SPEC05 generation.
- Audit/replay tests: complete ID/revision/hash/config/fence/reason manifest; candidate-to-audience/proposition/unit traversal; replay reads immutable payload and never invokes provider; reproduction labeled separately.

## Likely bypass hotspots

- Repository/helper methods named `current`, `latest`, or `active`; partial fetches that omit uncertainty/assumptions/governance; permissive nullable gate inputs; generic `save/upsert` mutating immutable rows; foreign keys checked for existence but not exact cross-object closure.
- Supplemental unit propositions validated only for existence, not exact decision-time status/material strategy change; architecture prompt built from broad tenant retrieval; cache/idempotency keys missing tenant, slot, config, or canonical hash.
- Retry/fallback middleware silently switching model/config; async provider response committing without renewed fence/cycle-state check; parent candidate/evaluation copied to rewrite; heuristic status reused as release state; human edits bypassing knowledge ingestion.
- Prompt concatenation erasing trust boundaries; tools callable from model rather than stage allowlist; logs/context leaking secrets/private data; generation service importing publication/control-plane adapters; replay path calling generation.
